# simSSD —— SSD 固件模拟器

一个用 C99 写的、可运行的 SSD 固件行为模拟器：从 NAND 介质的时序与并行，
到 FTL 的映射 / 垃圾回收 / 磨损均衡 / TRIM / 坏块，再到掉电恢复与检查点，
每一层都能跑出可复核的数字。

它不是一个"演示用的玩具 FTL"：所有时间都走同一个虚拟时钟，
所有介质操作都真的在通道 / CE 上排队，因此**结论是可以被量出来的** ——
比如"条带化把 GC 从串行编程变成并行"、比如"后台 GC 在这个模型里其实是负收益"。

```
make          # 构建 build/ssd-sim
make test     # 构建并运行单元测试
make asan     # 带 ASan/UBSan 的构建
```

跑一个基准（100 万次随机写，结束后全量校验）：

```
./build/ssd-sim --bench=1000000
```

---

## 1. 设计取向

| 取舍 | 选择 | 理由 |
|---|---|---|
| 时间 | 单一虚拟时钟（ns），不依赖墙钟 | 结果可复现，速度只影响墙钟不影响结论 |
| 介质 | 事件驱动的通道 / CE 占用模型 | 并行度、通道利用率都是算出来的，不是假设的 |
| 数据 | 不存 payload，只存元数据 | 关心的是映射 / 搬移 / 时序，不是字节内容 |
| 并发 | 异步提交 + 完成回调 | 真实盘就是这样，"在飞的请求"是 SPOR 的核心难点 |
| 验证 | 跑完一遍全量读回校验 | 任何一层出错都会在 `verify` 这一行暴露 |

## 2. 目录与分层

```
include/
  core/     时钟、事件队列、位图、延迟统计、配置、日志、统计、内存池
  media/    几何编解码、NAND 设备（页/块状态、通道/CE、掉电、故障注入）
  ftl/      FTL、GC、磨损均衡、调度器、恢复
src/        对应实现
tests/      单元测试（smoke / media / ftl / ftl-s3 / sched / spor / s6）
config/     ssd.conf 示例配置
```

**介质层**（`media/`）：页有 `FREE / VALID / INVALID / PENDING / CORRUPT` 五种状态，
块有 `FREE / OPEN / CLOSED / BAD / UNKNOWN`。一个 CE 忙到介质操作结束才释放，
通道只在 `t_xfer` 期间被占用 —— 所以"4 个 CE 挂在 2 条通道上"能真的跑出并行。

**FTL 层**（`ftl/`）：页级 L2P 映射，异步写（提交即更新映射，完成回调对账），
写失败换页重试，TRIM，贪心 / Cost-Benefit 回收，动态 + 静态磨损均衡，坏块隔离。

**调度层**（`ftl/sched.c`）：闭环队列（qdepth 个请求同时挂在盘上），
请求完成一个补一个，空闲时段补后台 GC，延迟按百分位统计。

## 3. 各阶段做了什么，以及实测结论

下面每一条数字都是 `make test` 之外、用上面那条基准命令（或变体）跑出来的，
不是估算。

### S1 介质
几何（通道 / CE / die / plane / block / page）、CE 级时序与并行、运行时坏块、
故障注入、busy / 并行度统计。

### S2 FTL
L2P 映射 + 异步写。**"提交即更新映射"** 这条设计贯穿整个工程：
它换来的是 host 不必等介质，代价是后面每一步都要处理"页还没真正写进去"
这件事（重试、快照一致点、撕裂页，全是从这里长出来的）。

### S3 回收 / 磨损 / TRIM / 坏块
贪心与 Cost-Benefit 两种 victim 策略、动态 + 静态磨损均衡、TRIM 位图、坏块隔离。

- **后台 GC 默认关闭。** 没有真实空闲时段时，"每次 host 写后补齐水位"等于持续
  GC：垃圾还没攒够就回收，WAF 从 3.08 涨到 3.87、IOPS 从 155 跌到 123。

### S4 并发
闭环队列调度、延迟百分位、空闲时段后台 GC、每 CE 一个写入槽位 + 严格轮转、
回收条带化。

- **搬移必须条带化。** 把整块的有效页写进同一块，等于在同一颗 die 上排队编程：
  一次回收 ~390ms，其余 3 个 CE 全程围观，100 万请求里 83% 的虚拟时间都耗在这段
  串行编程上。改成轮转到各 CE 之后：虚拟时间 5490s → 2430s，IOPS 181 → 412。

### S5 SPOR（掉电恢复）
`nand_power_cut()` 打断所有在飞的操作：页编程变成**撕裂页**（CORRUPT），
擦除被打断的块直接判坏。上电后 `ftl_recover()` 从介质重建映射。

- 校验必须以"**host 收到完成通知的值**"（`ack`）为准，不能用提交值：
  掉电那一刻还在飞的请求丢掉是合法的。
- 同一 lba 的并发写可能乱序完成，所以 `ack` 要取 `max(seq)`，否则会报出
  并不存在的 mismatch（20 万请求里错 4 个）。
- 写序号必须从介质上取回并取 max（页内 seq / 持久化 seq），
  否则盘被 TRIM + GC 清空后序号归零，块年龄基线塌掉。

### S6 checkpoint / superblock / 间歇负载

**S6-a 检查点（`--cp_interval`）**
定期把 L2P 与块表下刷到 system 区；上电时读回快照，只扫"快照之后动过"的块
（活跃块位图：块一出池 / 一归还就置位，检查点后清空）。

| 拓扑 | 关闭检查点 | 间隔 8192 | 间隔 1024 |
|---|---|---|---|
| 1024 块，20 万写，9 次掉电 | 上电 138.24ms，扫 9171 块 | **46.38ms，扫 164 块** | 44.70ms |
| 同上，IOPS | 1888 | 1852（-1.9%） | 1586（-16%） |
| 8192 块，10 万写，3 次掉电 | 368.64ms | 116.52ms（IOPS -17%） | 间隔 65536：285ms（IOPS -1.6%） |

- 收益随容量线性放大（全盘扫是 O(块数)，读快照是 O(元数据)），
  但**间隔必须跟着容量放大**，否则下刷元数据本身会吃掉 host 带宽。
- 快照必须是**一致点**：异步写提交时映射就改了，若照抄当前映射，
  快照会记下"指向还没写进去的页"的条目，把旧版本一起丢掉
  （掉电后新页是撕裂页，旧页又不在扫描范围里）。所以下刷前按
  `inflight_old` 临时回滚这些写，刷完再还原。
- 快照是"整份照搬"的，不过 `page_usable()` 这道过滤，所以恢复后要补两刀：
  按持久化的 TRIM 位图断开映射（否则 host 删掉的数据死而复生），
  以及作废指向无效页的悬空映射。

**S6-b superblock 条带写（`--striping`）**
按 superblock 分配：一次把整组块（每个 CE 一块）都填上，组内块的写指针同步推进，
于是一起写满、一起变成回收候选。GC 因此能一次收一整批。

- **批量回收只在后台 GC 生效。** 前台也批量时：一次回收的停顿变成 N 倍
  （max 322ms → 933ms、p99.9 119ms → 140ms），而 WAF 与并行度一点没变好
  —— 搬移本来就条带化了，批量带来的只是"同一段时间干更多活"，
  正好撞在 host 在等的那一刻。
- 批量回收能不能成立，全看补块额度：一次收 N 块就最多借 N 块，
  擦掉几块就最多借几块，池子净变化为 0（单块回收沿用"最多补一块"的老规矩，
  那时多补一块就是真吃老本）。
- 后台场景下批量确实优于单块：IOPS 927 vs 914、p99.9 130ms vs 137.7ms。

**S6-c 间歇型负载（`--burst_len` / `--idle_us`）**
每轮发 N 个请求、等它们落地，然后空转一段 —— 空转期间队列是空的，
这才是后台 GC 唯一能干活的窗口。

- 有了真 idle 之后，后台 GC **仍然是负收益**（50 万请求、9% 空闲时间）：

  | | IOPS | p99.9 | 前台 GC | 后台 GC |
  |---|---|---|---|---|
  | `bg_gc=0` | **948** | **119ms** | 1947 | 0 |
  | `bg_gc=10` | 927 | 130ms | 1515 | 435 |

  空闲时段确实替 host 做了 435 次回收，但总耗时反而更长：
  GC 的"读一批 → 写一批"之间有数据依赖，**独占盘时只能串行**；
  而 host 忙时做前台 GC，它的读写能与 host 请求在不同 CE 上重叠。
  "没人抢带宽"并不等于"干得更快"。
  附带一条：后台会把最划算的 victim（有效页最少的块）提前收走，
  留给前台的都是硬骨头，前台单次停顿因此变长。

### 顺带修掉的一个真 bug
故障注入下跑出 `req retries 0 (errors 198)` —— 重试次数记在**槽位**上而不是
**请求**上，槽位循环复用导致计数一路累积，跑几轮之后每个槽位的 attempts 都超过
上限，此后所有编程失败都被直接判死。更要命的是失败后映射仍指向那个没写进去的页，
于是这个 lba 新旧两版都读不到：一次可恢复的编程故障被放大成数据丢失。
修复（重试按请求计数 + 失败回滚映射）后：`errors 198 → 0`，`verify PASS`。

## 4. 当前基线（默认配置，100 万次随机写）

```
IOPS            413
write           p50 16.2ms | p90 34.3ms | p99 131.3ms | p99.9 263.6ms | max 521.1ms
ce util         70.7%        parallelism  2.83 of 4 CE
WAF             3.291        GC count     11850
checkpoints     122 次，15033ms（占 host 时间 0.6%）
PE cycles       min 10 / max 13 / avg 11.6 / stddev 0.57
verify          PASS (mismatch 0)
```

（默认配置已开启检查点：`--cp_interval=8192`。纯写 + 不掉电的场景下它只吃掉
0.6% 的 host 时间，换来的是掉电时上电快两三倍。）

## 5. 常用配置

全部选项见 `./build/ssd-sim --help`，也可以写进配置文件（`config/ssd.conf`）
用 `--config=file` 加载，命令行参数覆盖文件。

```
几何   --channels --ce --dies --planes --blocks --pages --page_size --spare_size
时序   --t_prog --t_read --t_bers --t_xfer          (ns)
可靠   --pe_limit --ecc --factory_bb --fault_inject --fault_rate
策略   --gc_policy(0=greedy 1=cost-benefit) --bg_gc --wl --wl_pe_thresh
       --workload(0=uniform 1=hotspot) --hot_percent --trim_ratio
并发   --qdepth --read_ratio
SPOR   --power_cut
S6     --cp_interval --striping --burst_len --idle_us
```

几个值得试的组合：

```
# 掉电恢复：每 2 万请求掉一次电，看 torn pages 与重建成本
./build/ssd-sim --bench=200000 --power_cut=20000

# 检查点有多大用：大盘 + 掉电，对比上电时间
./build/ssd-sim --blocks=1024 --bench=100000 --power_cut=25000 --cp_interval=0
./build/ssd-sim --blocks=1024 --bench=100000 --power_cut=25000 --cp_interval=8192

# 间歇负载下后台 GC 到底有没有用
./build/ssd-sim --bench=500000 --burst_len=2000 --idle_us=200000 --bg_gc=0
./build/ssd-sim --bench=500000 --burst_len=2000 --idle_us=200000 --bg_gc=10

# 最严苛组合：故障注入 + 掉电 + 间歇负载 + 后台 GC
./build/ssd-sim --bench=100000 --power_cut=10000 --fault_inject=1 --fault_rate=2 \
                --bg_gc=10 --burst_len=500 --idle_us=100000
```

## 6. 验证

```
make test
[smoke]  32 checks      [media] 147 checks
[ftl]    4468 checks    [ftl-s3] 3567 checks
[sched]  47 checks
[spor]   3481 checks    [s6] 14018 checks
ALL PASSED
```

测试覆盖：几何编解码、页 / 块状态机、通道与 CE 占用、故障注入、
映射与读写、GC 两种策略、磨损均衡、TRIM、坏块隔离与抢救、调度器、
掉电与恢复（撕裂页 / 过期页 / 写序号），以及 S6 的检查点一致点、
TRIM 不复活、superblock 分配、批量回收、间歇负载。

基准自带的全量校验是最后一道关：跑完 N 次写之后逐个 lba 读回，
`verify` 这一行必须是 `PASS`。

## 7. 已知限制

- **检查点是全量下刷。** 真实盘还会做增量检查点 + 日志重放，
  把"读快照"这笔固定开销也省掉（代价是每次 host 写都要额外写一笔元数据）。
  本模型选了位图方案：只在"块出池 / 归还"这种低频事件上动元数据。
- **没有日志（journal）。** 恢复靠"快照 + 扫活跃块"，不是重放日志，
  所以上电仍有 O(活跃块数) 的介质读。
- **负载模型偏简单。** 只有均匀 / 热点 + 递增 seq，读写混合只有固定比例，
  没有 trace 回放，也没有可调的 Zipf 参数。
- **没有 superblock 的持久化。** 批次标记是纯 DRAM 状态，掉电即失，
  恢复后新分配的块会重新建立批次；恢复后的第一次回收会退化成单块。
- **通道只建模了 `t_xfer` 独占。** 没有建模通道仲裁冲突、多 plane 的
  并发限制（同一 plane 内的操作其实不能并行）。
- **不模拟 DRAM 容量约束。** 映射表假定整个驻留内存。
